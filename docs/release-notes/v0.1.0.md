# SecureShare v0.1.0

SecureShare is a self-hosted one-time secret delivery service for securely sharing passwords, API keys, credentials, and sensitive text without leaving permanent plaintext copies behind.

## Highlights

- One-time secret links with explicit reveal and atomic consumption
- HashiCorp Vault Transit encryption
- No plaintext secret storage in PostgreSQL
- Optional password-protected links with failed-attempt limits
- Flexible structured, text, and JSON payloads
- Scoped API clients with one-time-visible client secrets
- OpenAPI 3.1 and locally served Swagger UI
- Optional SMTP link delivery and safe customizable templates
- English and Persian recipient experiences with Jalali dates in Persian
- PostgreSQL-backed users, roles, sessions, and theme preferences
- Audit events, Prometheus metrics, health checks, and version metadata
- Docker Compose deployment and responsive light/dark UI

## Security Design

SecureShare generates raw tokens with cryptographic randomness, places them in URL fragments, and stores only an HMAC lookup value. Recipient pages remove fragments immediately and hold the raw token only in page memory. Opening a page does not consume a delivery; the recipient must explicitly POST a reveal request.

PostgreSQL atomically leases one active delivery for consumption, preventing concurrent successful reveals. Payloads are encrypted through Vault Transit, and successful consumption blanks the retained ciphertext before returning plaintext once. Recipient pages use no-store cache controls and a strict CSP, while application logs exclude sensitive bodies, credentials, raw links, tokens, and Authorization headers.

SecureShare's backend handles plaintext briefly during Vault encryption and recipient reveal. It is not zero-knowledge or end-to-end encrypted.

## Quick Start

```bash
git clone https://github.com/Operalith/secureshare.git
cd secureshare
cp .env.example .env
docker compose up -d --build
curl -fsS http://localhost:8080/health/ready
```

The credentials in `.env.example` are for disposable local development only and are rejected by production validation.

## API

- Swagger UI: `/docs`
- OpenAPI 3.1: `/openapi.yaml`
- Version metadata: `/version`
- Readiness: `/health/ready`

See the repository README and `API.md` for authentication, payload, and integration guidance.

## Known Limitations

- Local Docker Compose uses Vault dev mode.
- SMTP delivery is synchronous.
- Rate limiting is in-memory and not coordinated between instances.
- Production multi-instance deployments require shared rate limiting and session storage.
- Historical email resend is unavailable because raw link tokens are not stored.
- SSO, LDAP, MFA, SMS OTP, asynchronous delivery queues, and multi-tenant isolation are not part of v0.1.0.

## Upgrade Notes

No upgrade path is required; this is the initial public release.
